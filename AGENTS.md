# AGENTS.md

Build the Blender 5.1 FluidSim Warp add-on from the synthesized requirements only. Keep simulation GPU-resident, support interactive viewport playback, preserve the listed FluidSim features, and use the synthesized Python modules for enums, kernel inventory, dispatch/custom-kernel contracts, UI behavior, profiling, and validation targets. The live field-storage contract is a sparse tiled leaf grid: fixed 8x8x8 leaf tiles addressed through a flat leaf table, without hierarchical tree storage.

## Verified workflows

- From the repo root, run `python tools/run_production_gate.py` for the default headless gate; add `--include-gui` (or set `FLUIDSIM_FULL_GUI_ACCEPTANCE=1`) for the full production gate, including interactive GUI acceptance and saved-demo timeline playback/report validation.
- To isolate the GUI lane, run `blender --factory-startup --python tests/blender_gui_acceptance.py`; validate a generated saved-demo playback report with `python tools/validate_gui_playback_report.py artifacts/gui_playback_probe.json`. These are non-background checks; the full gate wires the playback probe to `demos/dam_break.blend`.
- To run the saved-demo playback probe directly, set `FLUIDSIM_PLAYBACK_BLEND=demos/dam_break.blend` and `FLUIDSIM_PLAYBACK_REPORT=artifacts/gui_playback_probe.json`, then run `blender --factory-startup --python tests/blender_gui_playback_probe.py`; validate the report with `python tools/validate_gui_playback_report.py artifacts/gui_playback_probe.json`.
- For interactive playback performance changes, run `FLUIDSIM_USER_PATH_PROFILE=1 python tools/run_production_gate.py` or the focused `blender --background --factory-startup --python tools/profile_user_path.py -- --frames 6 --voxel-size 0.08 --max-particles 200000 --collider-subdiv 2 --json-out artifacts/user_path_profile.json` profile.
- Run the full Python regression suite with `python -m pytest -q`; use the production gate for Blender/CUDA/runtime changes because it invokes Blender 5.1's bundled Python and acceptance lanes.
- For deep-module refactor or ownership changes, run `python -m pytest -q tests/test_sourcing_pipeline.py tests/test_mesh_source_pipeline.py tests/test_pressure_projection_regressions.py tests/test_memory_safety_recovery.py tests/test_performance_hotpath_contracts.py tests/test_snippet_library.py` for the focused non-Blender contract lane.
- For GPU solver timing changes, run `"C:\Program Files\Blender Foundation\Blender 5.1\5.1\python\bin\python.exe" tools/profile_gpu_solver.py --device cuda:0 --frames 8 --warmup 2 --json-out artifacts/gpu_solver_profile.json`.
- For standalone runtime regression checks, run `blender --background --factory-startup --python tests/blender_cache_export_pipeline.py`, `blender --background --factory-startup --python tests/blender_memory_safety_gate.py`, `blender --background --factory-startup --python tests/blender_handler_persistence_gate.py`, and `blender --background --factory-startup --python tests/blender_viewport_2frame_gate.py`. For full background add-on acceptance and viewport attribute visualization, also run `blender --background --factory-startup --python tests/blender_background_acceptance.py` and `blender --background --factory-startup --python tests/blender_attribute_viz_acceptance.py`.
- For evaluated mesh source/sink acceptance, run `blender --background --factory-startup --python tests/blender_mesh_source_acceptance.py` and expect `MESH-SOURCE-ACCEPTANCE-PASS`; this verifies modifier-evaluated triangle emission, live solver advancement, and watertight Solid sink rejection without fallback.
- For the stock Blender 5.1 GPU viewport API boundary, run `blender --background --factory-startup --python tests/blender_gpu_viewport_api_probe.py` and expect `GPU-VIEWPORT-API-PROBE-PASS`; this checks exposed GPU types/state and `POST_VIEW` registration only, not visible shader drawing, pixels, or viewport performance.
- For focused ST-FLIP and surface validation, run `blender --background --factory-startup --python tests/headless_spatiotemporal_validation.py -- --device cuda:0`, `blender --background --factory-startup --python tests/headless_stflip_benchmark.py -- --device cuda:0 --frames 6`, and `blender --background --factory-startup --python tests/headless_stflip_timeline_viewport.py -- --scene demos/dam_break.blend`.
- For decoupled surface-resolution acceptance, run `blender --background --factory-startup --python tests/headless_surface_resolution_pipeline.py -- --device cuda:0 --particles 500000 --frames 24`.
- Build demos with `blender --background --python tools/build_demo_scenes.py`; use `-- --list-scenes`, `-- --standard-cache-scenes`, or `-- dam_break crown_splash` to select targets.
- Verify saved demo files with `blender --background --python tools/check_demo_blends.py`, then analyze outputs with `python tools/analyze_demos.py`.
