    What this mocks

    1. Deck bar (bottom). Transport, live readout with a ms/frame sparkline, the pending chip, Liquid Preview toggle, palette, wheel, bake ring. Each button names its operator in its tooltip. Spec: Deck bar.
    2. Emitter gizmo. Drag the arrow head to set emitter_velocity (LIVE class: chip goes green, no reset). Drag the dial ring to set emission_rate.
    3. Domain handles. Drag the right-face handle to resize the domain. While dragging, the padded grid and cell count preview; on release the chip shows Reset pending with the reason and an Apply button (RESET class).
    4. Collider. Click the crate to toggle Dynamic (4.0 rigid coupling). A dynamic crate floats and gets pushed.
    5. Liquid Preview. Toggle in the Deck or with L: particles become a screen-space surface with absorption, Fresnel rim and foam. Mesh build is skipped; the PointCloud stays published underneath.
    6. Command palette. Ctrl+K. Fuzzy list of operators, presets, demos and settings with inline values; numbers edit in place.
    7. Radial wheel. Right-click in the viewport. Six slots per stage; the hub cycles Setup → Simulate → Look → Bake.

    Rules the real build must keep

    1. Deck holds no state; every control writes the panel's property or calls its operator (parity test).
    2. Modal only owns events over Deck hit regions; elsewhere PASS_THROUGH.
    3. Colours derive from the active Blender theme at register time (this page hard-codes the dark theme look).
    4. Liquid Preview reads the already-published position array; no second readback.
    5. Deck OFF leaves every existing UI test byte-identical.
