Windows release without losing higher-value local behavior. Produce dual

## Audit result

Against the adjudicated integration:

- 119 of 153 files are byte-identical and are **already present**.
- 27 implementation files are byte-identical to the original pre-adjudication
  1.0.252 GPT candidate. They contain no unique 1.0.253 implementation value
  and must not overwrite the current combined owners.
- Seven files are genuinely new to 1.0.253: manifest, version, changelog, three
  documentation files, and third-party notices.

The 27 stale implementation copies include playback, bake, output publication,
pending settings, admission, solver settings, cache, diagnostics, device
preferences, capacity refresh, CUDA reduction, frame output, source-quality
recovery, registration, and solver behavior. Replacing current files with
those copies would reintroduce already-proven regressions.

## Collision decisions

1. **Implementation:** retain the current 27 adjudicated owners. Re-run their
   collision contracts after the version/platform adaptation; do not copy them
   from the archive.
2. **Release identity:** adopt version 1.0.253.
3. **Product platforms:** adopt explicit Windows x64 and Linux x64 support, but
   keep supported, packaged, and runtime-validated platforms distinct.
4. **Blender compatibility:** retain the target's Blender 5.1 minimum unless a
   real 1.0.253 API/runtime failure proves 5.2 is required. Manifest parsing
   alone is not runtime proof.
5. **Generated manifest metadata:** keep `[build.generated]` out of the tracked
   source manifest. Require the builder to add the correct single platform and
   empty wheel list to each produced archive.
6. **Runtime dependency:** retain external Warp 1.16.0 and bundle no Blender,
   Warp, CUDA, Python, or platform runtime.
7. **Documentation:** adopt truthful 1.0.253 identity/platform wording only
   after executable evidence. Preserve local product contracts such as exact
   Euclidean Cone/Pyramid boundary distance.
8. **Missing source-only release work:** adapt the existing local builder and
   tests from the package contract. Do not claim the archive supplied or proved
   builder/CI changes that it omits.

## Stop conditions

Stop rather than guessing if:

- the integrated Windows artifact cannot install or enable in Blender 5.1;
- a 1.0.253 feature demonstrates a genuine Blender 5.2-only API requirement;
- platform packaging would require bundling an unapproved runtime;
- cleanup cannot distinguish stale FluidSim installs from unrelated user data;
- live Crown Splash output cannot be distinguished from cache/static output;
- a collision has unique behavior on both sides without a shared-owner or
  executable basis for the combined resolution.

## Definition of done

The 1.0.253 work is complete only when the highest-value compatible behavior
from both sources is preserved, dual no-runtimes artifacts are verified, the
exact Windows artifact is installed and enabled from the expected path, Crown
Splash proves real handler-driven simulation, the production gates pass, and
the final branch remains reviewable with no unrelated dirty work.
