# Export visibility review repair

Review of PR #51 at `1aa88b75b2d8d8d6030306479a27b64835f33e4a` found that visibility requests were discarded while an exporter held the viewport policy. A cached-frame publication can create an output absent from the exporter's original visibility snapshot; releasing the hold therefore left that output with the wrong viewport visibility.

Held requests now enter the existing deferred scene queue. A timer dispatched during a hold retains the queue and retries after 0.01 seconds. The first dispatch after the outermost release reapplies current policy, outside the frame-change handler. No solver, cache, export geometry or render-visibility contract changes.

Validation on Windows CPython 3.11, with external pytest plugin autoload disabled:

- Parametrized timer regression with zero, one and two holds: before repair, two failures and one pass.
- `python -m pytest -q -o addopts= tests/ui/test_liquid_preview.py fluidSim_warp_blender51/tests/test_interchange_source.py`: 58 passed in 5.57 seconds after repair.
- Independent source review of the repair found no further actionable issues.

Blender crash/export acceptance and the production gate remain outstanding; these CPU checks do not establish runtime or release acceptance.
